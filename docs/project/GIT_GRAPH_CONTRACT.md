# Git graph learning contract

One SIMULATED delivery incident, independent of artifact/revision practice. Initial title/summary/source names are neutral. Six pre-repair fixture sources disclose delivery checks, approved base/PR head, parent records, job checkout selection, produced checkout/metadata SHA and intended integration request.

Incident: PR head forks from an earlier root and lacks the approved base. The request requires an immutable integration commit with first parent approved base and second parent reviewed PR head. A competing two-parent candidate integrates a different head. This is an explicit request policy, not a universal rule that all delivery commits must have two parents.

Before repair: six source ID/fact pairs plus relation are drafted, cloned and locked with a causal class. Completeness is separate from correctness; locking never reports whether the answer is correct. Wrong source/fact/relation/class cannot be rescued by later recovery or explanation. Checkout selection is the only repair; every candidate can build green. Explicit verification reports actual consumed-commit match and ordered direct-parent match separately, then combines them with canonical pre-repair diagnosis. Explanation follows verification and remains a separate mutable draft.

Changed transfer uses a linear replayed two-commit series, with an approved base reachable across two parent edges. Original PR-head identity is absent from that ancestry. The changed request requires base ancestry plus exactly reviewed fixture changes [p1,p2]; a later descendant adds p3 and fails despite retaining base ancestry. The learner reports selected immutable commit, its parent count, base/original-head ancestry, linked source facts and relation. Traversal computes ancestry and ordered linear change series, not merely a replacement SHA comparison. Change IDs are stipulated fixtures, not Git patch-id, semantic equivalence or signature verification.

Persistence: compose graphPractice into the existing shared Git/CI checkpoint. Schema4 adds state; fixture4 adds incident/transfer corpus. V3 and older shared checkpoints intentionally discard, including old artifact/revision progress. Linux remains schema7/fixture5. Graph-only reset clears graph while preserving siblings; whole Git/CI reset clears all and remounts local selection drafts. Editing explanation revokes explanation/transfer; editing transfer revokes pass; rebuild/reverify revoke downstream work. Rationale remains immutable until reset. Strict canonical snapshots, run tuple, recomputed verification and completion invariants reject inconsistent/forged derived flags. Consistent client forgery remains possible and non-authoritative.

Security: pure finite in-browser transitions. No learner Git, YAML, shell, host, network or credential execution. Object IDs/logs are synthetic, not observations from the user's machine or Actions runner. No trusted mastery/certification claim. Required tests cover all existing flows plus source/fact/class errors, wrong two-parent candidate, transfer contract change, cloning, revocation, fresh/draft/locked/completed refresh, stale/corrupt state, denied Storage getter/methods, mobile overflow, visible focus and absent runtime errors. CI checks out and asserts exact PR-head SHA, then runs install/typecheck/all Node tests/audit/build/locked Chromium/all production tests before merge.

Rollback: revert the product PR. Previous schema3 code rejects schema4 checkpoint rather than granting retrospective progress. Re-read LIVE main before any continuation.


## Observed SHA input mechanics

Rationale/explanation facts can bind SHA tokens from the learner-selected captured source. Explanation repair binds from its selected intent source. Changed transfer history/request facts bind from their selected visible transfer sources; selectedCommit binds from the linked history source. Candidate lists are extracted from raw output, never from validator answers. The learner chooses identity, order, source and causal predicates. Clear/undo modify ordinary persisted drafts and use existing explanation/transfer revocation; rationale controls remain inside the locked fieldset. Malformed manually entered facts remain editable but must be cleared/corrected before structured binding. No schema, fixture or scoring change.
